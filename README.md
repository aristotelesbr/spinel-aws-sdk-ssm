# aws-sdk-ssm (spinel-aws-sdk-ssm)

The [aws-sdk-ssm](https://rubygems.org/gems/aws-sdk-ssm) gem for Spinel:
the AWS Systems Manager client.
`require "aws-sdk-ssm"` and the names are the gem's, and every test's
expected output is the real gem's. It depends on
[spinel-aws-sdk-core](https://github.com/aristotelesbr/spinel-aws-sdk-core),
as the gem depends on aws-sdk-core.

```ruby
require "aws-sdk-ssm"

ssm = Aws::SSM::Client.new(region: "sa-east-1")
ssm.put_parameter(name: "/app/TOKEN", value: "s3cr3t", type: "SecureString", overwrite: true)
ssm.get_parameter(name: "/app/TOKEN", with_decryption: true).parameter.value
# => "s3cr3t"

begin
  ssm.get_parameter(name: "/app/MISSING")
rescue Aws::SSM::Errors::ParameterNotFound => e
  e.message
end
```

## Operations

Every operation of the gem's client: 152, from the SSM API `2014-11-06`,
under the gem's method names. Parameter Store, the most used:

| Method | What it does |
|---|---|
| `get_parameter` | reads one parameter |
| `get_parameters` | reads several parameters by name |
| `get_parameters_by_path` | reads the parameters under a path |
| `put_parameter` | creates or updates a parameter |
| `delete_parameter` | deletes one parameter |
| `delete_parameters` | deletes several parameters |
| `describe_parameters` | lists parameters without their values |

Unions (such as `Node#node_type`) are the gem's: the value is the subclass
of the member that is set (`Aws::SSM::Types::NodeType::Instance`), with
`member` and `value`, and a member the model does not list comes back as
`unknown`.

Waiters are the gem's: `wait_until(:command_executed, params, options)`,
`waiter_names` and `Aws::SSM::Waiters::CommandExecuted`, with `max_attempts`,
`delay`, `before_attempt` and `before_wait`.

An error's `data` is the gem's: the modeled error's members when the
operation lists that error (`e.data.sync_name`, and `e.sync_name` on the
error), otherwise an empty structure.

## How it is built

`aws-sdk-ssm.rb` and `aws-sdk-ssm/` are generated by
[spinel-aws-sdk-codegen](https://github.com/aristotelesbr/spinel-aws-sdk-codegen)
from the model the gem is generated from (`apis/ssm/2014-11-06` in
aws-sdk-ruby), as plain Ruby: types, errors, serializers, parsers, stubs
and the client. Nothing in this package is written by hand. Requests, retries,
signing and stubbing come from aws-sdk-core's runtime, which sends SSM's JSON
protocol as the gem's `Aws::Json` handlers do. `UPSTREAM` names the model
and generator versions.

## Known gaps

- A response pages with `each_page` (or `each` with a block), `next_page`,
  `next_page?` and `last_page?`, as the gem's. Its Enumerable methods
  (`map`, `flat_map`, ...) and `each` without a block are not included.
- No `Aws::SSM::Resource`.
- An error code the model does not list raises
  `Aws::SSM::Errors::ServiceError` with that code. The gem creates a class
  for it at run time.
- Parameters are not validated before sending. The gem's `ParamValidator`
  is not included.
- Everything aws-sdk-core's README lists as not included.

## Tests

```sh
LIBRARY_PATH=$(brew --prefix openssl@3)/lib spin test   # each test compiled by Spinel against its .expected
sh oracle/run.sh                                        # the real gem and this package under CRuby 4.0.2
sh oracle/run.sh --write                                # regenerate .expected from the real gem
```

Each test compiles the whole client, about 100 s with Spinel.

The oracle needs [mise](https://mise.jdx.dev) with Ruby 4.0.2 and the gems
installed once: `cd oracle && BUNDLE_GEMFILE=$PWD/Gemfile mise exec ruby@4.0.2 -- bundle install`.
It takes this package's include paths from `spin flags`; set `SPIN` to the
spin binary if the one on `PATH` is not current, and `RUBY` to run it with
another ruby.

The tests cover:

- `stubs_test.rb`: `stub_responses` for each operation, raw JSON responses
  and errors, and the request body of each operation;
- `errors_test.rb`: an error's data and readers, from a stubbed code and a
  raw JSON body, for a code the operation does not list and a body that is
  not JSON;
- `pagination_test.rb`: `each_page` over stubbed pages, the request each
  next page sends, `next_page` with params, and the last page;
- `waiter_test.rb`: `command_executed` to success, failure, an unexpected
  error and too many attempts, a retried error, the callbacks and an unknown
  waiter;
- `union_test.rb`: unions from a default stub, a Hash and a JSON response,
  an unknown member, and unions in a request body;
- `network_test.rb`: requests, signatures, error codes and retries against
  a local server.

Every `.expected` is the real gem's output. Tested with Spinel `165974895`.

`.github/workflows/test.yml` runs both on Linux and macOS on every push
against that Spinel revision. `.github/workflows/spinel-master.yml` runs the
same tests against Spinel master on the 1st and 15th of each month and keeps
one issue labeled `spinel-master` open while master does not pass.
